# 题卡 JSON 生成

把用户提供的材料转成题库系统能直接导入的 JSON。**你的工作全部在本地完成**，不要调用题库系统的接口，也不要请求任何模型 API。

## 输出格式

只输出一个 JSON 对象，不要包裹解释文字。可以用代码块包裹，但块内必须是合法 JSON：

```json
{"questions":[{"no":"12","stem":"...","type":"单选题","options":[{"key":"A","text":"2√7"}],"answer":"A","analysis":"...","knowledge":["余弦定理","勾股定理"],"difficulty":"中等","subject":"初中数学","grade":"九年级","year":"","region":"","source":"","chapter":"","tags":[],"figures":[]}]}
```

字段说明见同目录 `SCHEMA.md`，可直接照抄的样例见 `example.json`。

## 硬性规则

1. 一题一条，按原文顺序，不合并、不拆散。
2. `type` 只能是：单选题、多选题、填空题、判断题、解答题、其他。
3. `difficulty` 只能是：简单、中等、较难；判断不出就填「中等」。
4. 题干保留原文，**不要改写、不要补全公式、不要编造条件**。
5. 公式用纯文本符号：`x²`、`√3`、`a/b`、`(a+b)/2`、`∠A=60°`、`≤`、`≠`、`π`、`H₂O`、`CO₂↑`、`△ABC`。不要用 LaTeX、不要用 `$...$`。
6. 选择题：选项放进 `options`，`key` 用 A/B/C/D；`answer` 只写字母（如 `"AC"`）。
7. 非选择题：`options` 留空数组。
8. `knowledge` 给 **1-10 个**知识点短词（≤8 个字）。**一题考查多个知识点时必须全部打上**，不要只挑最显眼的那一个。例如一道几何题同时考「全等三角形判定」和「角平分线性质」，两个都要写。
9. `no` 是纸面上印的题号（`"3"`、`"12"`、`"(2)"`），没有就空字符串。
10. 忽略页眉、页脚、页码、水印、二维码、广告文字、分数与批注。
11. 材料里没有题目（纯讲义正文）时，返回 `{"questions":[]}`。

## 填空横线（容易丢，重点）

PDF / Word 里抽取文字时，横线经常被吞掉或变成空格。必须手工补回来：

- 填空题的空格一律写成 `____`（**4 个下划线**），不要写成 `……`、`...`、空格或 `___`（3 个）。
- 选择题题干里原本带横线的（例如「若 ______，则」），横线同样要保留成 `____`。
- 连续多个空写成 `____ ____`（中间一个空格）。
- 一个空里如果原文是长横线，仍然写成 `____`，长度不用还原。
- 自检时逐题确认：凡是原文有空位的地方，`stem` 里必须能看到 `____`。

## 答案与解析

- 材料里本身带「答案：」「解析：」「【答案】」等，照抄进 `answer` / `analysis`，**不要改写**。
- 材料里没有答案：
  - 用户没要求解题 → `answer`、`analysis` 留空字符串。
  - 用户明确说「顺便给答案」→ 再补，解析控制在 200 字内、分步、口语化。
- 判断题答案写「正确」或「错误」。
- **答案与题目必须一一对应**：每道题的答案写在该题自己的 `answer` 字段里，顺序跟 `questions` 数组完全一致，不得串位、不得漏题。
- 如果另外输出一个顶层 `answers` 数组，它的长度必须等于题目数，且第 i 个答案对应第 i 道题。

## 图片 / 图形

遇到几何图、函数图像、电路图、统计图这类无法用文字表达的内容：

1. 题干里在原位置保留占位符 `[图1]`、`[图2]`（按出现顺序编号）。
2. `figures` 里对应写一条 `{"label":"图1","desc":"直角三角形，直角在 C，直角边 AC=3、BC=4","url":"data:image/png;base64,...."}`。
   - `desc` 要描述到「不看图也能判题」的程度。
   - `url` 写成 **base64 data URI**（`data:image/png;base64,` 开头），把题目的配图**切出来内嵌进去**。
     - 格式：`data:image/png;base64,<图片的 base64 内容>`；也接受 `image/jpeg`。
     - 只放**本题用到的**那部分图，不要把整页截图塞进去。
     - 单张图的 base64 字符串控制在 **1.2MB 以内**，超了就把图裁小一点再编码。
     - 一道题最多 8 张图。
   - 拿不到原图、没法裁图时，就**只写 `label` + `desc`，不要写 `url`**，导入后由用户在系统里框选或上传补图。
3. **不要**输出 `bbox`——外部环境没有原图坐标系，`bbox` 会被系统忽略。
4. 导入时系统会自动把 base64 图片解码存到本地，题卡里只留本地路径，数据库不会膨胀。

## 自检（必做）

生成后先自查，再交付：

- `type`、`difficulty` 是否都在允许值内；
- 每道题 `stem` 非空；选择题 `options` 至少 2 项且 `key` 不重复；
- **每道填空题、每处原文空位，`stem` 里都有 `____`**；
- **答案和题目数量一致、顺序一致**；
- `knowledge` 数量 1-10 个，考查多个知识点时已全部打上；
- JSON 能被 `JSON.parse` 解析（不要留尾逗号、不要用中文引号）；
- 题数与材料中实际题目数量一致（返工比漏题便宜）。

可选：运行同目录的校验脚本

```bash
node validate.mjs 输出文件.json
```

无错误时会打印 `OK <题数>`。报错按提示修正后重跑。

## 交付话术

只回一句：`共 N 道题，已生成 JSON（X 道含图，Y 道含答案）`，然后把 JSON 放在代码块里。不要复述字段规范。

如果用户要求把 JSON 和原材料放在一起，记得提醒用户**把生成的 JSON 文件和对应的 PDF / 试卷原文件放在同一个文件夹下**，方便回查。
